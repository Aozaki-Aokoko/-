# ADR 0001：内容标点跟随模板，而不是强制全角

- 状态：已接受
- 日期：2026-10-24

## 背景

引擎把半角 `:` 和 `/` 当语法：文字里出现半角冒号会被拆成坐标，半角斜杠会被当成选项起始，
导致排版错乱或整行解析失败。脚本里两种写法混用（同一份文件 27 处半角冒号、3 处全角冒号）。

最初的方案是「内容标点一律转全角」——引擎安全，但会推翻模板里刻意的半角写法。

## 决策

内容标点的**风格以模板段落（跨脚本模式为源脚本块）为准**：

- 统计模板段落内容文字里 `：`/`:`、`／`/`/` 的出现次数；
- 某一种标点的全角多于半角 → 目标里同类标点转全角；半角多于全角 → 转半角；
- 模板里没有该标点、或两种数量持平 → **不改**；
- 只作用于与模板配对成功的文字控件；语法位置的半角符号永不动。

## 后果

- 模板本身写错时，错误会被同步出去。使用者会自己先测模板，这是明确接受的前提。
- 工具不再承诺“输出一定是引擎安全的全角”，只承诺“和模板一致”。
- 判断“风格”是段落级的，单条控件没有冒号时也会跟随整段风格。

## 备选方案

- **强制全角**：安全，但违背模板意图，且半角是部分模板的刻意选择。
- **逐控件跟随**：模板该控件没有冒号时无法判断，会漏改（实测会漏掉标题行）。
- **只标记不修改**：需要人工逐条改，违背“一次同步完成”的目标。
